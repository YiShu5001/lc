## 4. 已实现与缺失对照

### 4.1 任务定义与层间接口

论文内容：

- 面向移动目标的协同包围/占位任务
- 上层输出高层速度意图
- 下层控制层负责稳定执行
- 成功、终止、约束条件要明确

当前实现情况：

- 已实现二维高层动作 `vx, vy`
- 已实现基础目标占位误差和成功判定
- 已有控制层映射接口 `integration/interfaces/mapper.py`

主要缺口：

- 当前 mapper 只把二维动作压成单一标量控制参考，不是完整二维速度接口
- 尚未显式实现“规划周期保持”
- 尚未实现更完整的终止条件，如越界、目标丢失
- 动作约束目前主要是 `[-1,1]` 裁剪，缺少更明确的速度变化率约束链路

判断：

- `部分实现`

### 4.2 局部观测建模

论文内容：

- `self / obstacles / neighbors` 三路局部观测
- 邻机集合应体现局部感知图
- 可变数量实体要通过注意力处理
- 论文还提到对称破缺信息，例如 slot id / UAV id / priority token

当前实现情况：

- 三路结构化观测已实现
- 可变障碍物/邻机数量通过 padding + attention 处理
- 最近 `top-k` 邻机逻辑已在 Critic 中实现

主要缺口：

- 还没有显式感知半径 `R_sense` 下的动态图边集建模
- Actor 里没有显式 mask 机制区分“有效实体/填充实体”
- 没有加入对称破缺 token，例如 `slot_id`、`uav_id`
- 当前 `self_state` 没有纳入目标速度、剩余速度裕度等更丰富自状态

判断：

- `主体实现，细节未完`

## 5. 当前最关键遗漏

按“对论文真实性影响”排序，当前最关键的 5 个遗漏是：

1. 当前环境没有真正实现动态目标和动态障碍
2. 当前环境不是严格的多无人机联合仿真，而是近似协作环境
3. Critic 不是完整联合动作 Critic
4. 控制层接口还是简化版，没有完整二维速度引用闭环
5. 缺少更正式的 replay 统计与多种子实验协议

## 6. 建议补充计划

### 第一优先级：补环境真实性

目标：

- 让第四章环境更接近论文任务本身

建议动作：

- 为目标加入真实运动模型
- 为障碍物加入真实动态模型或至少可配置运动
- 加入越界、目标丢失等终止条件
- 明确感知半径和有效邻接关系

原因：

- 这一步对论文真实性提升最大

### 第二优先级：补多机真实性

目标：

- 从“单主体 + 代理邻机”推进到“更真实的多机协作训练/评估”

建议动作：

- 环境显式维护多无人机状态
- 观测来自真实邻机相对位置
- formation/angle 误差基于真实群体状态计算
- 训练时至少支持共享策略下的群体 rollout

原因：

- 这是第四章“协作”是否站得住的核心

### 第三优先级：补控制接口闭环

目标：

- 让规划层输出更自然地落到控制层

建议动作：

- 把当前单标量 `mapper` 改成完整二维速度参考映射
- 加入规划周期保持或插值机制
- 显式记录规划层到控制层的接口变量

原因：

- 这样第四章和第三章的系统连接才更完整

### 第四优先级：补 Critic 和 replay 细节

目标：

- 提升训练解释性和与论文表述的一致性

建议动作：

- 评估是否引入邻机动作 token
- 精化 cooperation 的 contribution 公式
- 增加 replay 层采样比例与样本质量统计图
- 固化 rare event 判据

原因：

- 这一步更偏“让方法更像论文最终版”

### 第五优先级：补实验协议

目标：

- 让第四章实验更完整、可复现、可比较

建议动作：

- 加多随机种子重复
- 加阶段内和阶段间 ablation
- 增加环境复杂度横向测试矩阵
- 将关键超参数落入配置

原因：

- 这一步决定最后结果展示质量

1. 动态目标与动态障碍

3. 控制接口二维映射闭环
4. Critic 与 replay 细化
5. 多种子实验与更完整图表
